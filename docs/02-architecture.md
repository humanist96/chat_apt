## 2.3 데이터 흐름

```
1. 데이터 수집
   GitHub Actions (Cron)
   → Railway (Crawler)
   → 네이버 부동산 / 공공 API
   → Supabase (저장)

2. 데이터 분석
   Supabase (원본 데이터)
   → Railway (Analysis Engine)
   → 유사도 계산 / 저평가율 산정
   → Supabase (분석 결과 저장)

3. 사용자 요청
   User → Cloudflare CDN
   → Vercel (Next.js)
   → Railway (API)
   → Supabase (조회)
   → Response

4. 인증 흐름
   User → Vercel
   → Supabase Auth (OAuth)
   → JWT 발급
   → API 요청 시 검증
```

## 2.5 API 엔드포인트 설계

| Method | Endpoint | 설명 | 인증 |
|--------|----------|------|------|
| GET | /api/listings | 매물 목록 조회 | 선택 |
| GET | /api/listings/{id} | 매물 상세 조회 | 선택 |
| GET | /api/apartments/{id}/transactions | 실거래 이력 | 선택 |
| GET | /api/apartments/{id}/similar | 유사 아파트 | Basic+ |
| GET | /api/analysis/{listing_id} | 저평가 분석 | Basic+ |
| GET | /api/analysis/{listing_id}/report | 상세 리포트 | Premium |
| POST | /api/favorites | 관심 매물 등록 | 필수 |
| GET | /api/user/usage | API 사용량 조회 | 필수 |
