# 데이터베이스 비교 분석: PostgreSQL vs OpenSearch

## 현재 구성 (PostgreSQL/Supabase)

### 장점
| 항목 | 설명 |
|------|------|
| **관계형 데이터** | 아파트-매물-거래 간 관계 표현에 최적 |
| **ACID 트랜잭션** | 결제, 구독 등 정합성 중요한 데이터 처리 |
| **Supabase 통합** | Auth, RLS, Realtime 등 기능 무료 제공 |
| **SQL 표준** | 복잡한 JOIN, 집계 쿼리 용이 |
| **무료 티어** | Supabase 무료: 500MB DB, 50,000 MAU |
| **Row Level Security** | 사용자별 데이터 접근 제어 내장 |

### 단점
| 항목 | 설명 |
|------|------|
| **전문 검색 한계** | LIKE 검색은 느림, Full-text 설정 필요 |
| **스케일링** | 대용량 시 샤딩 복잡 |
| **실시간 분석** | 집계 쿼리 성능 제한 |

---

## OpenSearch (http://49.247.172.187:9200)

### 장점
| 항목 | 설명 |
|------|------|
| **전문 검색** | 아파트명, 주소 등 텍스트 검색 최적화 |
| **실시간 분석** | Aggregation으로 빠른 통계/집계 |
| **수평 확장** | 클러스터 구성으로 무한 확장 |
| **Dashboard** | OpenSearch Dashboards로 시각화 |
| **유사도 검색** | Vector search로 유사 매물 검색 가능 |
| **로그 분석** | 크롤링 로그, 에러 추적에 적합 |

### 단점
| 항목 | 설명 |
|------|------|
| **관계형 데이터 부적합** | JOIN 불가, 비정규화 필요 |
| **트랜잭션 없음** | 결제/구독 데이터 저장 부적합 |
| **운영 복잡도** | 클러스터 관리, 인덱스 설계 필요 |
| **리소스 사용량** | PostgreSQL 대비 메모리 많이 사용 |
| **보안 설정** | 기본 admin:admin은 변경 필수 |

## 결론 및 권장사항

### 1단계 (현재)
- **PostgreSQL만 사용** - MVP 단계에서는 충분
- 데이터 모델 검증 후 확장

### 2단계 (사용자 증가 시)
- **OpenSearch 추가** - 검색/분석 전용
- PostgreSQL → OpenSearch 동기화 파이프라인 구축
- 검색 쿼리만 OpenSearch로 라우팅

### 보안 주의사항
```
⚠️ OpenSearch admin:admin 계정은 즉시 변경 필요!
- 새 사용자 생성
- 역할 기반 접근 제어 설정
- SSL/TLS 활성화 권장
```
